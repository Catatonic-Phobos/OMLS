# Layer 0.9 — Physical Power Fabric / MCU (protocol stub)

**Status:** landed on `main` (tag `v0.9.0`)  
**Depends on:** 0.4 envelopes (optional budget hints)

## Goal

Treat energy as a schedulable resource via a **power-fabric message schema** and an in-process **simulator MCU** — no physical switching hardware.

## What this layer owns

- Protocol messages: `hello`, `status`, `set_budget`, `ack`, `telemetry` (`schema_version: "0.9"`).
- Simulated rails (12V / 5V / 3V3) with budgets, draw, and soft over-budget warnings.
- Envelope → budget hint (`EnvelopeBudgetHint` from sustain/performance intensity).
- Master `RunDemo` attaches envelope budgets to its simulator and notes them in policy/summary.
- CLI: `omls power show|hello|budget`.

## Boundaries

| In 0.9 | Deferred |
|---|---|
| In-process MCU simulator | Real MCU / PMBus / smart PSU |
| Soft software budgets | Hardware-protected switching |
| Envelope intensity → watts hint | Full power topology scheduling |

## Key surfaces

- Package: `internal/power`
- Examples: `examples/power/messages.yaml`
- CLI: `omls power …`
- Fabric: `Server.Power()` simulator used by `RunDemo`

## Lab notes

Always warns that the MCU is simulated. Over-rail budgets are accepted as soft hints with warnings — never crash.
