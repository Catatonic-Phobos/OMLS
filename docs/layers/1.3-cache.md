# Layer 1.3 — RAM cache reservation

**Status:** userspace reservation on a peer  
**Depends on:** 1.1 cluster membership (peer addresses), 1.2 honest join

## What landed

- Each daemon listens on `:7444` for a single RAM reservation (anonymous memory, `mlock` when the kernel allows it).
- `omls cache place` picks the other joined node, reserves up to 512 MiB (max 1 GiB, and at most half of that node's available RAM), and copies a slice into it.
- `--kind memory` copies resident pages of The Sims 4 (anonymous memory when the kernel allows the read, otherwise file pages the process already has in RAM).
- `--kind graphics` copies the game window with `xwd`.
- The peer reads the bytes back before `place` reports success. `omls cache status` shows reserved and filled sizes.
- `omls cache serve` is the same listener, for a node whose daemon was started from an older binary.
- `omls status` refreshes every second with per-node CPU, RAM, disk, GPU, and how that usage and any reservation are split across the cluster.

## Out of scope

Moving the game's live heap or the GeForce framebuffer onto the other GPU. The other node stores a copy in its own RAM. The Sims process keeps running on the machine that opened it.
