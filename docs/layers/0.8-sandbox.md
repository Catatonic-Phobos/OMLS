# Layer 0.8 — Driver sandbox / VFIO-UIO (userspace stub)

**Status:** landed on `main` (tag `v0.8.0`)  
**Depends on:** 0.1 RDL resource model

## Goal

Provide a **userspace-safe sandbox abstraction** that probes for VFIO/UIO, can declare sandboxed resources in the Machine Profile / graph, and offers a dry-run claim path — without requiring real passthrough hardware.

## What this layer owns

- Probe `/sys` (+ `/dev`) for VFIO/UIO presence (best-effort; fixture `--sys-root`).
- Declare `class: sandbox` RDL resources when backends are detected.
- Simulated `claim` that never binds/unbinds host drivers.
- Clear unsupported warnings on typical VMs with no VFIO/UIO.
- CLI: `omls agent sandbox probe|list|claim`; `omls agent discover --sandbox`.

## Boundaries

| In 0.8 | Deferred |
|---|---|
| Probe + dry-run claim | Real VFIO bind/IOMMU groups |
| RDL sandbox class | Community experimental drivers |
| Sysfs fixtures in tests | Kernel module loading |

## Key surfaces

- Package: `internal/sandbox`
- RDL: class `sandbox` (+ schema enum)
- CLI: `omls agent sandbox …`

## Lab notes

Cloud/lab VMs usually report `backend=none` with a warning — that is success. Claims always set `simulated: true`.
