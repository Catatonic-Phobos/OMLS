# Layer 0.4 — Resource Envelopes (delivered)

**Status:** on `main` as `d6a457a` (`feat(0.4): Resource Envelopes with best-effort Linux backends`)  
**Depends on:** 0.3 work units / agent execution path

## What landed

- **Envelope schema** (`internal/envelope`): ADSR-style `attack` / `peak` / `sustain` / `release` with performance levels and thermal max.
- **Presets:** `balanced`, `high`, `eco` + YAML examples under `examples/envelopes/`.
- **Backends (best-effort):**
  - `duty-cycle` — always (userspace pace/sleep)
  - `cgroup-cpu` — cgroup v2 `cpu.max` when writable
  - `cpufreq` — `scaling_max_freq` when writable
- **CLI:** `omls agent envelope validate|show|apply`
- **Fabric hook:** optional `envelope_yaml` on each work unit; `run-demo --preset` / `--envelope` attaches it.

## Lab notes

On typical cloud VMs, cgroup/cpufreq often warn and fall back to duty-cycle — expected. Envelope never fails the demo if backends are missing; controller clamps on `limits.thermal_max_c`.
