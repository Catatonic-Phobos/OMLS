# Layer 0.6 — Adaptive scheduling

**Status:** landed on `main` (tag `v0.6.0`)  
**Depends on:** 0.3 Learning Plane, 0.4 envelopes (optional cost hint), 0.5 behavior priors

## Goal

Move beyond EWMA-only `Adjust` toward an explainable **multi-signal** policy with **hysteresis**, so worker allocation does not thrash every demo round.

## What this layer owns

- **Policies:** `ewma` (0.3 default) and `adaptive` (0.6).
- **Multi-signal score:** duration EWMA, CPU load, temperature / headroom, locality + virt (WSL penalty), optional envelope intensity cost, spare capacity.
- **Hysteresis:** cooldown rounds after a blend move; thermal escape still overrides cooldown.
- **CLI / RPC:** `omls master run-demo --policy adaptive` → `RunDemoRequest.policy`.
- Explainable `policy_note` strings including per-node score breakdowns.

## Boundaries

| In 0.6 | Deferred |
|---|---|
| Weighted blend + cooldown | ML models / neural policies |
| Envelope cost as intensity hint | Full power-fabric budgets → **0.9** |
| In-process policy selection | Community profile priors → **0.7** |

## Key surfaces

- Package: `internal/learn` (`adaptive.go`: `ScoreNode`, `AdaptiveAdjust`, `EnvelopeCostFromYAML`)
- Proto: `RunDemoRequest.policy`
- CLI: `omls master run-demo --policy ewma|adaptive`

## Lab notes

Missing load/temp signals stay neutral in the blend (never crash). Single-node demos still run; rebalancing needs ≥2 available nodes.
