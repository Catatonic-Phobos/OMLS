# Layer 0.7 — Community hardware profiles

**Status:** landed on `main` (tag `v0.7.0`)  
**Depends on:** 0.1 RDL facts, 0.5 Behavior Profiles (prior seed)

## Goal

Share reusable Machine+Behavior **snippets** with provenance/confidence so a master can apply soft priors when a joining node matches arch/virt/model heuristics.

## What this layer owns

- YAML schema `community_version: "0.7"` (`internal/community`).
- Catalog load from `community/`, `profiles/`, or `examples/community/`.
- Provenance: source, author, confidence level + score.
- Match rules: arch, virt, `model_contains`, os_family (best-effort).
- Priors: duration/temp-delta EWMA + synthetic sample weight.
- CLI: `omls community list|show|import [--dir DIR]`.
- Master: `--community-dir`; on `AdvertiseProfile`, apply prior only if the node has **no** local Behavior observations yet.

## Boundaries

| In 0.7 | Deferred |
|---|---|
| Local YAML catalog + heuristics | Distributed profile sync / signing |
| Soft seed into Behavior store | Driver sandbox isolation → **0.8** |
| Example snippets | Manufacturer profile plane |

## Key surfaces

- Package: `internal/community`
- Examples: `examples/community/*.yaml`
- CLI: `omls community …`, `omls master serve --community-dir`
- Behavior: `Store.ApplyCommunityPrior`

## Lab notes

Matching is best-effort. Missing community dir → empty catalog (warning-free). Local ObserveWork samples always override community priors.
